# الدليل التقني — MVP 0.2.0

## البنية

Modular Monolith في Python 3.12: ingestion → document_reading/ocr → classification → extraction/validation → database/archiving/search → FastAPI وواجهة HTML/CSS/JavaScript عربية. الواجهة تخدمها العملية نفسها دون CDN أو خطوط ويب أو تحليلات أو Swagger خارجي. استُخدمت واجهة FastAPI محلية بدل Streamlit لتوحيد العملية والأصول وتقليل اعتماديات التشغيل؛ لا حاجة لخدمتين للواجهة والخدمة.

`application/service.py` ينسق وحدات العمل بقفل داخل العملية وقفل مجلد على مستوى النظام. محرك Tesseract محمّل محليًا مرة في العملية عبر tesserocr؛ لا subprocess لكل مستند ولا أوزان تُنزّل في Startup. SQLite WAL وFTS5 للتخزين والبحث، والملفات الأصلية خارج DB. النص الرقمي وOCR يمران في عقد Page نفسه.

الحالات received → processing → needs_review/failed، ثم completed بتأكيد بشري فقط. تعديل نتيجة مكتملة يعيد needs_review. حالات run تحفظ نتيجة المحاولة الأصلية؛ اكتمال المراجعة يخص Document وسجل تأكيد منفصل، فلا يغيّر حالة المحرك التاريخية. كل إعادة محاولة لها UUID ونصوص وحقول مستقلة.

## التشغيل والإعدادات

راجع README وخطوات دليل المستخدم. الإعدادات تقرأ SMARTGOV_DATA_DIR وSMARTGOV_MODEL_DIR وSMARTGOV_MAX_PAGES وSMARTGOV_MAX_BYTES. الأوزان العربية والإنجليزية مثبتة commit وبصمة في ocr-assets.json. استخدم عاملًا واحدًا؛ CLI يثبت الربط على 127.0.0.1 والمنفذ 8765 افتراضيًا. لا تستخدم `--workers` متعددًا؛ قفل المجلد يمنع العملية الثانية.

مجلد التشغيل: archive.sqlite3 وملفات WAL عند التشغيل، originals بأسماء UUID مشتقة من نوع المحتوى، incoming للملفات المؤقتة، و.process.lock. الملفات الأصلية لا تعدل. صلاحيات إنشاء المجلدات 0700 والملفات الحساسة 0600، وCLI يستخدم umask 0077. هذا لا يوفر تشفيرًا أو صلاحيات مؤسسية.

حد الحجم يطبق تدريجيًا أثناء الإدخال وقبل تحليل multipart في API (مع هامش صغير لتغليف الطلب). حدود الصفحات والبكسلات تفحص قبل التصيير. نوع الملف من التوقيع، والاسم الأصلي لا يستخدم كمسار. إدخال حجم زائد أو نوع غير مدعوم يرفض دون تسجيل مستند ناجح. فساد PDF ذي التوقيع المقبول يسجل محاولة فاشلة ويحفظ الأصل. تعطل العملية يعلّم المحاولات المتوقفة failed في التشغيل التالي، ويكتشف الأصل ذا UUID الذي وضع قبل انقطاع تسجيل DB لاستعادته في سجل فشل قابل لإعادة المحاولة.

## البيانات والمراجعات

جداول documents وruns وpages وclassifications وfields وreviews، وفهرس document_fts. حقول الاستعلام المهمة أعمدة علائقية، وتفاصيل العقود JSON موثقة ومتحقق منها. لا ملفات كبيرة داخل DB ولا جدول لكل مستند. نتائج المحاولات والحقول محفوظة، والمراجعات append-only ولها ترتيب تسلسلي. التصنيف المصحح يمكن أن يولد مرشحي حقول النوع الجديد من نص المحرك نفسه دون محو مرشحي النوع الأول.

تعديل الصفحة لا يغيّر نصها الأصلي، ويشترط إعادة فحص الحقول بعد آخر تغيير فعلي، بما فيه الرجوع إلى نص سابق. فهرسة النص والقيم الفعالة تتم في معاملة التصحيح نفسها. لا يمكن تصحيح حقل من محاولة أو تصنيف مختلف، وAPI يتطلب expected_run_id لمنع اعتماد شاشة قديمة. المراجعات القديمة تبقى قابلة للاسترجاع لكل محاولة.

SQLite FTS5 يستخدم unicode61 مع تطبيع أرقام عربية/فارسية وتشكيل وتطويل وعلامات اتجاه ومسافات محدود. لا توحيد همزات أو اشتقاق. كل جزء بحث يقتبس كعبارة حرفية، والاستعلامات SQL مع معاملات. فلاتر التواريخ تعمل على الميلادي المتحقق فقط؛ تجنب خلط تاريخ الرفع وتاريخ المستند.

## API المحلي

- GET /api/health وGET /api/documents: الصحة والبحث والفلاتر وlimit/offset.
- POST /api/documents: multipart باسم file، يحفظ ويعالج بصورة متزامنة متسلسلة؛ duplicate يعيد السجل الموجود.
- GET /api/documents/{id}: الحالة والنص الأصلي والفعال والحقول والمراجعات.
- GET /api/documents/{id}/original مع download=true اختياريًا: أصل مثبت البصمة.
- GET /api/documents/{id}/preview?page=1: معاينة PNG محلية مشتقة من الأصل، دون الاعتماد على إضافات المتصفح أو PDF.js خارجي.
- GET /api/documents/{id}/runs/{run_id}: نتيجة محاولة ومصادرها ومراجعاتها.
- POST .../retry وPOST .../reviews وPOST .../confirm: إعادة المحاولة والتصحيح والتأكيد.

كل طلب يغيّر البيانات يتطلب `X-Archive-Request: local`. الأصل في Origin يجب أن يطابق خدمة التطبيق، ولا CORS أو تفويض مؤسسي. Host مقيد وCSP بالأصول الذاتية، وDOM يستخدم textContent لا إدخال HTML من المستند. تؤكد API بشرط acknowledged=true، وتمنع صفحات OCR غير المراجعة والحقول غير المحسومة. يمكن قراءة مخطط JSON من /openapi.json؛ واجهات وثائق CDN معطلة.

## التراخيص والتغليف

الحزمة تستهدف Linux x86_64 وCPython 3.12 فقط. wheels مثبتة الإصدار والبصمة، وتثبيتها يستخدم --no-index و--require-hashes. التحقق الشامل من ملفات الحزمة في verify_bundle.py. يلزم توفر Python/venv/ensurepip وglibc المناسب مسبقًا؛ الحزمة لا تثبت نظام تشغيل أو Python، ولا تمثل حزمة Windows/macOS.

حزمة tesserocr 2.9.1 تحتوي مكتبات أصلية، منها libjbig 2.1 تحت GPL-2-or-later. سُجلت هذه الحقيقة وإشعاراتها ولا يكفي ترخيص MIT لربط Python لتغطيتها. التسليم هنا للاستخدام المحلي الداخلي لصاحب المستودع، ولم ينشر خارجيًا. إعادة توزيع حزمة ثنائية لطرف آخر تحتاج استيفاء تراخيص المكونات والتزامات المصدر واختيار ترخيص كود المشروع من مالكه؛ لم نفترض ترخيص نشر نيابة عنه. لاحظ أيضًا fpdf2 LGPL-3.0 لأدوات توليد بيانات التطوير (ليس اعتماد تشغيل التطبيق).

## الاختبارات والتقارير

pytest لاستخدام الأصول المحلية الحقيقية، scripts/verify_offline_reading.py لحجب المقابس وفحص الاختبارات ومسار API داخل ASGI. يسمح الأخير بتواصل IPC المحلي في سجل strace ولا يتجاهل محاولات AF_INET/AF_INET6. scripts/smoke_ui.py يفحص المتصفح والتحميل والتصحيح والبحث والاسترجاع والعرض الضيق ويرفض أي HTTP/WebSocket خارج loopback. سجلاته منفصلة عن التحقق من التثبيت الجديد دون شبكة.

التقييم المجمد الأول في evaluation/results/mvp-held-out.json محفوظ كما هو. إصلاح فقد فاصل PDF أُجري بعد تشخيص الاختبار؛ evaluation/results/mvp-regression.json فحص انحدار مكرر وليس تقييمًا مستقلًا. تفاصيل الدقة والقيود في تقرير التسليم. لا تستخدم النتيجة الاصطناعية كتقدير لدقة واقعية، ولا تُعتمد جودة OCR من نجاح اختبارات التخزين.

النسخ تحت قفل وحدة العمل وبواسطة SQLite backup، ثم أرشيف ZIP للأصول المرتبطة وبصماتها. الاستعادة إلى مجلد جديد فقط مع كشف traversal والروابط والملفات الزائدة والبصمات والعلاقات. ملفات إضافية وضعها المستخدم يدويًا خارج سجلات التطبيق ليست أرشيفًا مدعومًا؛ النسخة تشمل الأصول المرتبطة الموثقة فقط. لا تنسخ DB وحدها أثناء WAL ولا تعتبر النسخة مؤمنة بالتشفير.
